# A2A-to-MCP Security Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Docker Compose security lab where a root LLM agent delegates recursively through A2A, worker agents use MCP tools/resources, and a browser workbench captures, controls, and replays the complete chain.

**Architecture:** A FastAPI control plane owns scenarios, runs, policies, and an append-only PostgreSQL event log. A transparent gateway proxies the selected A2A and MCP operations, applies policies/faults, and publishes correlated events. Reusable agent and MCP fixture containers sit behind the gateway, while a React/Vite workbench consumes REST and SSE APIs.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, PostgreSQL 16, HTTPX, official A2A and MCP Python SDKs behind local adapters, React 18, TypeScript, Vite, React Flow, Vitest, Playwright, Docker Compose, pip requirements files, and npm lockfiles.

**Spec:** `docs/superpowers/specs/2026-11-15-a2a-mcp-lab-design.md`

## Global Constraints

- Compose starts a fixed topology: one root agent, one worker agent, two fixture MCP servers, one gateway, one control plane, one web UI, and PostgreSQL.
- MVP A2A operations are Agent Card lookup plus `send`, `get`, `cancel`, and `stream`.
- MVP MCP transport is Streamable HTTP with `tools/list`, `tools/call`, and `resources/read`.
- Mediated traffic is the default and the only mode with complete protocol capture.
- Policies freeze when a run starts; `approval_required` pauses the affected task and creates an auditable one-shot approval action.
- Every gateway event carries a run id, task id when available, agent id, protocol, operation, hop, request id, and a per-run sequence.
- Agent and MCP containers run as non-root with read-only root filesystems, no host mounts, bounded resources, and localhost-only published ports by default.
- Model calls go through the model proxy and are recorded as request metadata plus response; hidden chain-of-thought is never stored or rendered.
- Replay creates a new run from retained responses and fails clearly when a required body is redacted or destroyed.

## Review Focus

- A reconnecting SSE client must resume from `Last-Event-ID` without losing or reordering events; test in Task 2.
- Recursive delegation must stop at the configured depth and must not loop forever on a cyclic Agent Card; test in Task 4.
- A redacted or missing body must make replay non-replayable instead of making an external call; test in Task 7.
- Stream cancellation, timeout, malformed response, and duplicate delivery must produce deterministic task states and visible fault events; test in Task 3.
- An approval-required policy must pause, resume once on approval, and deny on timeout; test in Task 6.
